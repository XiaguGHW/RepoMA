## R13 — preserve the editing context

The rule editor retains its raw text independently of the parsed Codebook.
Its state includes initial text, dirty status, selection start/end/direction,
scroll position, validation error and saving status. Language changes update
editor labels without replacing the textarea or parsing unfinished JSON.

Workspace, session, model, material and Codebook transitions check this state.
Rejecting the explicit discard prompt retains the same editor and active
context. Cancel also requires confirmation when the draft is dirty. A native
beforeunload guard covers navigation with unsaved changes. Drafts are held in
memory; this does not promise crash recovery or persistence after discarding.

Saving still requires explicit confirmation. The textarea becomes read-only
while saving, and context transitions wait for that save. The GUI includes the
profile version it edited; a stale version receives 409 and leaves the raw
input and error visible. The optional version field preserves compatibility
with existing API callers. The UI updates its saved profile before another
edit can open. Saving modifies the app's rule draft only, retaining the source
Codebook bytes. Invalid or unconfirmed edits leave the stored profile unchanged.

## R14 — translate UI messages from structured records

workbench_i18n.UIMessage remains string-compatible for existing callers while
carrying a semantic message_key and parameters. Its payload preserves nested
UI messages, numeric counts and opaque file/model/source strings. Explicit
localization changes UI messages only; it never infers a translation from
arbitrary model or user text. Structured errors retain secret redaction in
both compatibility text and metadata.

The shared three-language catalog now covers prereading, summary reuse, dossier
creation/reuse/failure, model connection/generation/repair, streaming fallback,
Codebook parsing/edit errors, request/context errors and cache actions. SSE
progress/errors and final notices include message keys and parameters alongside
their compatible text fields. Cache responses, model tests and comparison
failures also expose structured messages. Reading scopes retain their existing
cache identity strings and add explicit display records.

CAD image groups now expose neutral name/count/overview/detail fields from the
document library. Their notices no longer interpolate preformatted Chinese
sentences. Existing attachment generation and legacy report fields remain intact.
Known material roles, index/OCR states and reading scopes have explicit UI labels.
Unknown technical diagnostics and legacy opaque text remain verbatim.

Classification/coverage cards retain their structured data and redraw labels in
the current language. Processing, notices, API errors, reasoning headings,
source/DFC panels, model-test status, cache actions and export labels use explicit
component records or data snapshots. Existing model answers, reasoning bodies,
user questions, paths, class names, rule text and source labels remain unchanged.
No whole-DOM dynamic text translator or translation observer was introduced.
Late history responses cannot overwrite an open rule editor. Workspace setup's
completion signal now follows its initial history/context-panel loads.

## R15 — drawer geometry and usable controls

no horizontal entrance translation. Inputs and action rows can shrink/wrap,
long paths/errors wrap inside the scrolling body, and scan-report positioning
overrides the persisted desktop splitter offset at the narrow breakpoint.

The chat header provides compact material/rule shortcuts when the context
sidebar is hidden. They remain available after the initial welcome screen is
replaced by chat history. Existing desktop styling and drawer workflows remain.
